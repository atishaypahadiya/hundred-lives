00 / Questions

Three questions. Each one is something I can count.

  • 01 diversity

    If I run one persona 100 times, how many meaningfully different paths come out?

  • 02 sensitivity

    If I change one detail, like hometown or degree, does what the agent does change?

  • 03 grounding

    If outcomes come from real data instead of the model's imagination, do the paths change?

01 / Why

Single answers are tested. Lives over time aren't.

Companies like Simile and Aaru now sell "synthetic people": LLM agents that stand in for real customers in surveys and product tests. The best published evidence for this, Park et al. (2024), shows agents built from two-hour interviews can answer survey questions about as consistently as the real person does two weeks later.

That evidence is about single answers at a single moment. Nobody has shown that an agent can stand in for a person over time, making a chain of decisions where each one changes what's possible next. That's the part people actually care about when they ask "what would happen if I did X," and it's the part this project tests.

In the Fragile Families Challenge, 160 teams with years of data could barely predict how families' lives turned out. So this isn't a forecast.

The project asks something smaller: whether the simulated paths respond to the inputs at all, or come out of the model the same way regardless.

02 / Persona

Every run starts from a file. The rest the agent works out by acting.

agents/personas/maya.yamldraft
name: Maya
born: 2004, San Jose, CA
family: parents run a small restaurant; first in family at a 4-year college
education: B.S. computer science, state school, graduating this spring
skills: [python, web dev, basic ML]
traits:
  risk_tolerance: medium      # the line changed in sensitivity runs
  patience: low
goal: become CEO of a company worth over $1B
starting_state:
  savings_weeks: 12          # how long she can go without income
  network: 3 classmates, 1 former internship manager
horizon: 260                 # turns; 1 turn = 1 simulated week

For the sensitivity tests, I copy this file, change exactly one line, and run both versions the same number of times.

03 / One run

One week per turn. 260 turns per life.

  1. Read state. The agent gets its persona, a summary of what has happened so far, the current week, and its remaining savings.
  2. Act. It makes as many tool calls as it wants within that week's budget: write code, post on the mock forum, message another agent, apply for something.
  3. World decides. Anything with an uncertain outcome, like an application, a pitch, or a launch, goes to the world model. The agent never decides its own outcomes.
  4. Log and advance. Every action and outcome is written to the trace, and the clock moves forward a week. Savings go down unless the agent has income.
  5. Compress memory. Every 13 weeks the agent writes a summary, and older detail is dropped. This keeps context, and cost, from growing without limit.

Step 3 is where the project lives or dies. In the first version the world model is another LLM acting as referee, the way Concordia's "game master" works. That has the same bias as the agent: it also believes the founder story. Later versions replace it with a table of real base rates, which is the third question.

06 / Measuring

A hundred paths, or three? Count them.

Reading 100 logs by hand doesn't scale, and "they all seemed similar" isn't a result. Each run gets reduced to a short sequence of milestones, like graduate → job → side project → quit → seed round, and the analysis works on those sequences.

QuestionMeasure
diversityCluster the 100 milestone sequences by edit distance, the method sociologists use to compare career histories. Report the number of path types and the Vendi score, an "effective number of distinct items."
sensitivityRun the original persona and a one-line variant 100 times each. Test whether the two sets of paths come from the same distribution (energy distance with a permutation test).
groundingSame comparison between the LLM referee and the base-rate world. Also compare how often each world lets the agent reach its goal against the real-world rate.

Baseline for all three: the same persona with the background stripped out, just the goal. If the full persona and the bare goal produce the same paths, the background isn't doing anything.

07 / Predictions

Written down before any runs. Marked right or wrong after.

  • diversityMost runs fall into two or three path types that read like a startup biography: quit the job, build in public, raise a round.untested
  • sensitivityChanging the hometown changes the wording of the logs more than the decisions. Changing risk tolerance matters more, because the model understands what it means for a choice.untested
  • groundingReal base rates change outcomes a lot and behavior a little. Most runs fail to raise money, but the agents keep trying the same moves.untested
  • refereeUnder the LLM referee, the share of runs that reach the goal is far above any real rate.untested

If these hold, that's still a result: it measures how much "synthetic person" behavior over time is the model's prior rather than the person.

08 / Limits & cost

What this can't tell you.

Not a forecastThis doesn't predict anyone's future, including the persona's. It measures how the model behaves.
Compressed timeFive years in an afternoon. The agent never gets tired, sick, or distracted.
A small worldThe mock web is much smaller than the real one. Some paths simply aren't available.
Test awarenessModels sometimes notice they're being tested. Runs where the agent mentions it are flagged.

Cost. The infrastructure is free and open source. The only real cost is API usage.

  • Development and early runs use local models through Ollama, at no cost.
  • Each run has a hard token budget, and the API account has a monthly spend limit.
  • The persona and instructions are cached instead of re-sent at full price each turn.
  • Routine turns use a small model. A larger one only writes the quarterly memory summaries.
